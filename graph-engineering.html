Graph engineering: split the work, keep the evidence

METHOD 01 / SAVED & CHECKED 19 OCT 2026 / SOURCE-LINKED EXPLAINER

The idea in plain English

Draw the work before adding more agents. Give each job a clear input and output. Run jobs together only when neither needs the other's result and they do not collide over files, accounts or limited services. Combine what came back, check it against real evidence, then produce one answer.

A graph is the dependency map, not necessarily a graph database, a visual town, or a fleet of LLMs. A node can be ordinary code, a human check or an agent. Some graphs contain loops; the first experiment can be a simple acyclic workflow.

The smallest useful pattern

Question -> independent source checks in parallel -> normalize and deduplicate -> verify -> one synthesis -> human review.

1. Define the jobs. Each one gets a bounded question, permitted sources and a fixed result shape. 2. Test every arrow. Does B need A's output? If not, remove the invented dependency. Still check shared files, rate limits and permissions. 3. Reduce before merging. Remove duplicate sources and normalize records with code. For large runs, combine batches without losing source links or unresolved exceptions. 4. Verify against an anchor. Use an independent check context plus the source, a test that actually ran, or an observed final state. Another model agreeing is not proof. 5. Count expected results. Mark failed or missing jobs explicitly; do not silently filter them out and call the report complete. 6. Put limits on the run. Cap scope, concurrency, retries, time and spend. Stop at human review before publication or external actions.

Example for this hub

Goal: compare three visual agent-world projects. - Three independent readers: one project each. - Each returns: name, canonical URL, what runs, evidence type, checked date, license caveat and unknowns. - Reducer: deduplicate redirects and normalize dates, without discarding missing records. - Checker: reopen primary sources, distinguish README claims from tests, and reconcile contradictions. - Synthesis: one comparison with all three outcomes accounted for. - Human gate: review only. No install, credential use, connection to private work or publication.

Use it when / skip it when

Use it for broad comparisons, independent source gathering and audits of separable files. Start with one agent when the task is small, exploratory, tightly coupled or needs frequent steering. Parallelism can reduce waiting; it does not guarantee lower cost or better judgment.

What to keep, qualify or leave out from the linked article

- Keep: the fake-edge test, explicit node contracts, fan-out/reduce/synthesize, hidden-resource dependencies, failure accounting and objective anchors. - Qualify: a fresh checker context can reduce anchoring, but is not fully independent evidence. A majority of model votes must not override a failed source check. Correctness, freshness and provenance are separate required checks, not a two-out-of-three vote. - Qualify: code-side handoff can spare the parent conversation from raw outputs. Any downstream model still processes its inputs; "zero extra context" is not a general zero-token guarantee. - Qualify: dynamic workflows are documented in current official Claude materials. Do not treat the word "workflow" as a universal switch that works identically in every client, account or version. - Leave out of the guide: the article's "5-10%" capability estimate, general speedup rhetoric and Bun rewrite cost/volume anecdote. Not independently established in this review and not needed to use the method.
