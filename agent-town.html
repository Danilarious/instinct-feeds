Cost evidence the first run missed

  • Smallville correction: the original Generative Agents paper explicitly says that simulating 25 agents for two days cost "thousands of dollars in token credits" and took multiple days. The October 15 report's statement that this figure was unverified was wrong. This is the authors' report, not an independently audited invoice or a current price quote. Generative Agents, section 8.1.
  • Lyfe Agents: the authors report about $0.50 per agent per human hour (figure 6 shows $0.51). Their roughly $25 Smallville comparison is a reconstruction in Appendix F, not a directly measured apples-to-apples benchmark: it assumes a $2,000 total, 16 waking game hours per day and a 10x game-to-real-time conversion. The conversion was not known from the original paper. These historical assumptions are not a present-day operating budget. Lyfe Agents, figure 6 and Appendix F.
  • Affordable Generative Agents: the full framework used 31.1% of baseline tokens in the three-person, two-game-day GPT-3.5-Turbo setup after policy reuse had accumulated. The 25-person result was 42.7%, not 31.1%. These are paper-specific token results, not universal dollar savings or guarantees for every model/world. Affordable Generative Agents, table 1 and figure 3.

Design ideas worth testing include Lyfe's option-action controller, cheap non-LLM checks and Summarize-and-Forget memory, and AGA's reusable lifestyle policies and social-relationship memory. The original spreadsheet-style cost model remains an estimate; use these studies as evidence for where to measure and optimize, not as replacement current prices.

1. Executive summary

  1. Fork, extend, or build: build a thin custom layer and borrow patterns. AI Town (MIT, Active, a16z-infra/ai-town) is the only active, general-purpose base, but it forces Convex and a 32px pixel pipeline. Borrow its three-clock tick, input queue, and one-file character data. Borrow hook-to-state plumbing from pixel-agents and Claude-Office. Treat Smallville and Concordia as reference reading only.
  2. Renderer: PixiJS v8 in its own canvas inside the draggable window. Phaser 4 is the fallback. Keep Konva for the host site. Skip Godot and Three.js for v1.
  3. Runtime: one local Node/TypeScript process (event-log hybrid) streaming events to the renderer over WebSocket. Move to Convex only for multi-viewer hosting. Replay from a recorded log for cheap public demos.
  4. Asset pipeline: Illustrator, Export for Screens PNG at 2x, one artboard per body part, optional atlas, code-driven rigid-part animation (bob, swing, squash). One illustrated background plus a walk mask, not a tile grid. Spine only if motion feels stiff.
  5. Cost (my estimates, order of magnitude): per hour for 3 / 10 / 25 agents: small hosted model cached about $0.06 / $0.20 / $0.49; tiered cached about $0.87 / $2.90 / $7.30; frontier cached about $7.47 at 10 and $18.70 at 25; local model $0 API. Levers: prompt caching, tier routing, scripted routine behavior, idle gating, replay.
  6. Simulated and real agents in one layer: yes, via one event schema ({agent, t, action, target, text}). Updated October 19: Miniverse plus the alpha Hermes bridge now provide a documented integration reference; see the second-run supplement. Deployment and production readiness remain untested. Telemetry alone need not add LLM inference, but message-driven agent replies can incur model costs.

Biggest risk: whether code-driven animation of your geometric characters reads as charming. The Friday test asset answers that.

4.1 Tick rate vs. LLM latency: decouple three clocks

The core fact: an LLM call takes seconds, rendering needs 16-33 ms frames. Every working system runs at least two clocks and joins them with a queue.

  1. Render clock (30-60 FPS, in the browser). Only interpolates and animates. Never waits on a model.
  2. Simulation clock (fixed step: movement, collisions, timers, queued plan execution). Cheap, deterministic, no LLM.
  3. Cognition clock (event-driven, seconds to minutes). LLM calls run async. They write intents into the sim as inputs ("move to cafe", "say X", "start conversation").

Techniques seen in the field:

Technique What it does Used by Cost to build
Action queue / locally executed plan LLM emits a multi-step plan once. Sim executes it step by step with no LLM calls Smallville plans daily agendas, then decomposes, then moves along paths [S2][S10] Cheap
Server steps at 1 Hz, ticks at 60 Hz inside a step, history buffer for the client Client replays the last second of positions so motion looks smooth even though state is saved once per second AI Town [S11] Medium (use their HistoricalObject pattern or copy the idea)
Optimistic movement + interpolation Client moves the sprite toward the target at once. Server state corrects later AI Town client replay; generic game pattern Cheap
Visible "thinking" state A bubble, spinner, or typing indicator while a call is in flight. AI Town tracks startTyping / finishSendingMessage as inputs so others do not talk over each other [S11] AI Town Cheap
Pre-computed replay Run the sim offline, save per-step movement, replay in the browser at any time Smallville replay route [S2] Cheap-medium
Parallel output streams Separate modules (talk, move, plan) run concurrently, with a coherence layer Project Sid PIANO [S12] Expensive. Overkill for 3-25 agents

Verified numbers. - AI Town: 60 ticks per second inside a step, steps run once per second, one world is single-threaded, input latency about 1.5 s as configured, step size can drop to 250 ms at the cost of more function calls and DB bandwidth [S11]. - Smallville: one game step = 10 game seconds. You run N steps with a run <step-count> command, and replay by URL [S2].

6. Custom art and rendering findings

6.0 Bottom line for this section

  • Almost every agent-town repo assumes a 32x32 pixel tileset and a small spritesheet per character. None of the ones I checked ship a high-res illustrated or vector style. You are building the art layer yourself, and the open-source projects are useful for the cognition and event layer, not for the look.
  • The most practical path for geometric Memphis/Bauhaus art: PixiJS v8 as the renderer, characters as layered vector parts rasterized to a texture atlas (2x to 3x), one hand-composed illustrated background with a separate invisible walk mask, and code-driven animation (squash, bob, swing) instead of frame-by-frame drawing. Add a skeletal tool (Spine or Rive) only if the code-driven motion feels too stiff.
  • Geometric flat-color art is unusually cheap to animate in code, because characters are built from simple shapes that can be moved, rotated and scaled independently. That fits your style and avoids hand-drawing walk cycles.

6.2 Vector sources: what to do with Illustrator art at runtime

Three options, from least to most vector-faithful:

  1. Rasterize at export (recommended default). Export PNG or WebP at 2x/3x from Illustrator, pack into an atlas, and let the GPU scale it. Pros: fastest at runtime, predictable, supports filters. Cons: soft edges when zooming past the export scale. Pixi supports this directly.
  2. SVG rasterized at load. Pixi Assets.load('x.svg', { resolution: 4 }) rasterizes the SVG into a texture. Convenient (you keep the SVG as source of truth), memory cost grows with resolution. V: PixiJS docs, https://pixijs.com/8.x/guides/components/assets/svg
  3. SVG as live vector Graphics. Pixi parses the SVG into geometry, stays crisp at any zoom, can be edited dynamically (recolor strokes, change shapes). Pixi docs warn it can be expensive to parse for intricate illustrations. Best for flat-color geometric props with few paths. V.

Practical rule for your style: characters and props = option 1 or 2 at 2x, simple decorative geometry (stripes, squiggles, confetti, floating shapes) = option 3, large backgrounds = option 1 with a size check against the 4096 cap.

6.4 World building: Tiled maps vs hand-composed backgrounds

Option A: Tiled tilemap (what every sim repo uses). - Tiled maps export JSON (V: https://doc.mapeditor.org/en/stable/reference/json-map-format/). Object layers hold spawn points, collision shapes and named zones (V: Phaser object layer docs, https://docs.phaser.io/api-documentation/class/tilemaps-objectlayer). - Tiled: 12,862 stars, last push 2026-09-02, license shows NOASSERTION in the API (mixed licensing, check before redistributing the editor, you only export data so this rarely matters). Active. - Tile art repeats on a grid (usually 32px). Illustrated, non-repeating Memphis compositions fight the grid. Tiles do work for repeating geometric patterns (floors, rugs), which is a fit for your style. - AI Town reads a Tiled export through a conversion script into data/gentle.js, and its issue threads show people struggling with it (blue background, wrong tile order, leftover original assets). V: https://github.com/a16z-infra/ai-town/issues/269 and https://github.com/a16z-infra/ai-town/issues/268. Treat the AI Town map route as brittle.

Option B: hand-composed illustrated background + walk mask (recommended). - Paint the whole room or town in Illustrator as one image (or a few layers: floor, mid, foreground). Draw a second, invisible layer in flat colors: white = walkable, black = blocked, optional colors = named zones (cafe, park, desk). - At runtime: pathfinding runs on a coarse grid sampled from the mask (for example 1 cell = 16 px of mask). Zones are rectangles or colors you read from the mask. This is a pattern, not a verified library recommendation. Tiled can also author the mask, using its object layer with polygons over your background image: you get the Tiled editing UI for collision and zones without tile-grid art (V: Tiled manual on objects, https://doc.mapeditor.org/en/stable/manual/objects/). - Depth/occlusion: to let characters walk behind a table or tree, cut those props into separate sprites and sort by Y (foot position). In Pixi, set zIndex from y with sortableChildren (UNVERIFIED as exact API naming for v8, check docs). - Cost: one big background is the single most art-heavy item but fully fits your skills. No grid constraints.

Option C: hybrid. Background is one image, props are separate sprites placed in a Tiled object layer. Best long-term, adds one step now.

6.9 Risks specific to this art route

  • Atlas and texture limits. Keep each atlas under 4096x4096 (Pixi's stated SVG-texture cap, mobile GPUs also commonly cap here, UNVERIFIED).

  • Mirroring breaks asymmetric details.
  • Konva and Pixi in one page each own a canvas. They do not share scene graphs.

Move to Convex only when you need public multi-viewer. Rationale for not choosing B: Python wins on research code, but you pay with a bridge to a React site. Rationale for not choosing C: highest cost, least leverage from your assistant.

Local feasibility check (estimate, hardware numbers unverified). 375k output tokens per hour is about 104 tokens per second sustained, and 6.5M input tokens per hour is about 1,800 tokens per second of prompt processing. A single consumer GPU running a small model with batched requests can plausibly reach this. A laptop likely cannot at 25 agents. I did not benchmark Ollama here. Unverified. The practical fix is to lower the call rate (see techniques) rather than buy hardware. At 3-10 agents local is comfortably fine.

Sensitivity. Costs scale linearly with call rate. Halving act frequency to one per two minutes cuts about 29% of input tokens in my profile (75k of 260k) and 31% of output (4.5k of 15k). Dialogue length is the next lever. Output tokens dominate cost on the frontier config: 15k x $20 = $0.30 of $0.75 cached.

8.2 What newer projects do differently (as stated in their READMEs)

  • Cut LLM calls where behaviour is routine. Agentshire's default mode is a state machine with templates and 400+ preset lines at zero LLM cost, and only "Soul Mode" uses the LLM in three tiers (plan, tactical, dialogue). AI Town agents "use a combination of simple rule-based systems and talking to an LLM" (ARCHITECTURE.md).
  • Run models locally. AI Town supports Ollama; mkturkcan runs on 16 GB VRAM or less; StarNet offers an Ollama path; TinyTroupe added experimental Ollama support in 0.6.0.
  • Separate the world engine from the agent. AI Town splits convex/engine from convex/aiTown and convex/agent; Concordia separates entities from a Game Master.
  • For real agents, observe rather than simulate. pixel-agents and pixtuoid capture hooks and transcripts and never prompt an LLM for the visualization.
  • Make the UI honest. StarNet README: "the interface must never assert state the harness cannot prove."
  • Make runs replayable. AgentSociety uses JSONL replay with DuckDB reads.
  • Guard the event channel. pixel-agents treats its session URL token as a bearer secret and gates hook installation on it.

9. Recommended starter path: first weekend

Goal: a local-only sandbox where 3 agents with your art walk around a custom background, with fake or scripted "thoughts", before any LLM wiring. This proves the art pipeline, which is the riskiest, least-documented part.

9.2 What to strip or avoid

  • No Convex, no vector DB, no backend LLM calls this weekend.
  • No Tiled tile conversion scripts. No 32px tile grid.
  • No Spine, no Rive, no Lottie in the character path.
  • No React-managed per-frame state: React owns the window shell and UI panels, Pixi owns the animation loop. Pass events in through a small store or event emitter.

9.3 Build order

Friday evening (about 2 hours): the single test asset. Draw one character in Illustrator in your Memphis/Bauhaus style as separate named layers: head, torso, left arm, right arm, left leg, right leg, plus eyes open/closed and mouth closed/open. Use a front view and a side view. Put each part on its own artboard, same size, so Export for Screens makes one PNG per part. Choose a visible accessory (a geometric hat) so flip direction is obvious. Convert strokes to outlines, avoid filters and gradient meshes. Why this asset: it exercises parts, anchors, flipping, talk states and tinting in one object.

Saturday morning (about 3 hours): empty window, one character. 1. npm create vite@latest (React + TypeScript) in a scratch folder, add pixi.js and pixi-filters. (Package names, V from search results and repo pages.) 2. Component TownWindow: a div with a ref, create a Pixi Application in useEffect with resolution: devicePixelRatio, destroy on unmount. 3. Load the PNG parts, assemble in a Container with pivots at the feet, add idle bob and blink using the ticker. 4. Implement walk: swing arms/legs by sine, flip the container's x scale for west. 5. Ask Claude Code for step 2 to 4 with the part names; give it the naming convention in 6.6.

Saturday afternoon (about 3 hours): world. 1. Paint the background (one room or a small plaza) at about 1600x1000, export @2x. Check against the 4096 cap. 2. Paint the walk mask in flat black/white at 1/4 scale. Add 3 zone colors. 3. Load the mask into an offscreen canvas, read pixels into a walkable grid, run A* (write or import a small library, UNVERIFIED which one). 4. Click-to-move for the test character; verify he avoids blocked areas. 5. Add 2 props as separate sprites and sort by y to test occlusion.

Sunday morning (about 3 hours): 3 agents, scripted. 1. Tint-recolor the character twice (white-masked parts + tint) to get 3 agents. 2. Write a tiny event stream: a JSON array of {agent, t, action: "move"|"say"|"idle", target?, text?}. Drive the scene from it. This same event format later accepts both LLM-simulated agents and real OpenClaw/Hermes logs (the one-spectator-layer idea, final design belongs to run 2/merge). 3. Add speech bubbles as DOM overlays positioned from sprite coordinates (easier to style with Tailwind than Pixi text). 4. Add one OutlineFilter on hover/selection and one HslAdjustmentFilter hue-shift effect for "thinking" (both from pixi-filters, V docs).

Sunday afternoon (about 2 hours): drop it into the retro-OS window. 1. Wrap TownWindow in your existing draggable window component. Test drag, resize and minimize. Make sure Pixi pauses its ticker when the window is hidden or minimized. 2. Confirm no WebGL context errors alongside your existing Konva/WebGL content. 3. Measure frame rate with 3 characters, then spawn 25 copies to see headroom.

9.4 Definition of done for the weekend

  • One illustrated background, one walk mask, one character with idle/walk/talk, 3 tinted agents driven by a scripted event stream, running in a draggable window locally.
  • A written list of what felt stiff in animation (decides whether Spine is worth buying) and what felt heavy in drawing (decides whether to cut directions or parts).

9.6 Direct opinions on the art-related decisions

  1. Fork? No. Build thin, borrow event and character-data patterns from AI Town, behavior ideas from Smallville.
  2. Renderer? PixiJS v8, separate canvas inside the window.
